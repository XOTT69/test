# Оселя Mini App — технічне завдання та реалізація v1.0

## 1. Призначення
Приватний сімейний менеджер домашнього догляду всередині Telegram. Один інтерфейс об’єднує осмос, картриджі, домашню аптечку, справи, покупки, витрати, статистику, сімейний доступ та налаштування нагадувань. Текстовий Telegram-бот зберігається для керування й повідомлень.

**Production Mini App:** https://oselya-telegram-bot.mikolenkoanton7.workers.dev/app

**Запуск:** користувач відкриває чат свого бота, натискає кнопку меню **🏠 Оселя**. Кнопку створює GitHub Actions через Telegram Bot API `setChatMenuButton` після кожного успішного деплою.

## 2. Візуальна система
- Mobile-first, якісний iOS-like інтерфейс без окремого браузера.
- Світлий фон `#f6f8ff`, основний текст `#111f4b`, акцент `#6556f6`, синьо-фіолетові градієнти, м’які тіні та великі округлення.
- Максимальна ширина контенту 540 px; адаптоване нижнє меню з урахуванням iOS safe-area.
- Навігація: **Головна · Осмос · Аптечка · Справи · Ще**. Розділ «Ще» містить покупки, витрати, статистику, сім’ю, налаштування.
- Статуси: 🔴 вже потрібна заміна/термін минув, 🟠 наближення заміни / малий запас, 🟢 у нормі.
- Модальні форми у форматі нижніх панелей; підтвердження небезпечних дій.
- Підтримка зниження анімацій за `prefers-reduced-motion`.

## 3. Екрани і поведінка

### Головна
- Привітальна картка та прямий перехід до плану.
- Лічильники фільтрів, справ, аптечки й покупок.
- Швидкі дії, найближчі заміни та справи.

### Мій осмос
- Перелік систем; створення і редагування назви, моделі й дати встановлення.
- Картриджі, прив’язані до конкретної системи.
- Створення/редагування картриджа; дата заміни, календарний інтервал у днях/місяцях або точна кінцева дата.
- Картка картриджа з кольором статусу, датою, залишком у місяцях і днях.
- Кнопка заміни, вибір фактичної дати та за бажанням вартості; наступна дата автоматично обчислюється за збереженим інтервалом.
- Історія замін зберігається у D1. Видалення картриджа потребує підтвердження.

### Аптечка
- Кожна упаковка з окремим терміном придатності — окремий запис.
- Назва, маркування/форма, залишок, одиниця, строк придатності, нижній поріг запасу, місце зберігання, примітка.
- Пошук за назвою/формою/місцем, фільтри за придатністю і запасом.
- Однокрокове поповнення чи списання одиниці та редагування; архівування.
- Придатність контролюється за термінами 30/7/1 день, у день закінчення та наступного дня; нульові й малі залишки сповіщаються окремо.
- Не надає порад щодо прийому/дозування. При використанні звірятися з упаковкою.

### Справи
- Активні, на найближчі 7 днів, завершені.
- Створення, зміна назви, дати та повторюваного інтервалу в днях.
- Кнопка «Виконано» переносить повторну справу на наступний термін.

### Покупки
- Додавання й редагування товарів та приміток; прапорець придбано.
- Спільний список для учасників сім’ї.

### Витрати та аналітика
- Ручне введення витрат, сума в гривнях.
- Витрати на заміни картриджів автоматично додаються за бажанням.
- Загальна статистика, графік витрат за місяцями, історія замін.

### Сім’я
- Власник створює одноразове запрошення (діє 24 год, максимум 5 запрошених).
- Запрошення відкриває приватний чат бота з `/start join_<код>`, власник сім’ї та запрошений користувач обмінюються доступом добровільно.
- Власник може відключати учасників, учасник може вийти.
- Усі домашні записи спільні, а параметри сповіщень — персональні.
- Учасник із раніше створеними власними даними має попередньо вирішити питання резервної копії — бот не переносить їх потай.

### Налаштування
- Увімкнення/вимкнення особистих сповіщень; попередження заздалегідь.
- Усі нагадування надходять від Telegram-бота, а не від відкритої сторінки.

## 4. Архітектура

| Рівень | Реалізація |
| --- | --- |
| UI | `src/miniapp-ui.js`: адаптивний HTML/CSS/JS без сторонніх frontend-бібліотек |
| API | `src/miniapp-api.js`: `GET /api/bootstrap`, `POST /api/action` |
| Server | `src/index.js`: Cloudflare Worker, webhook бота, сторінка `GET /app`, D1 |
| DB | `oselya-bot-db` у Cloudflare D1; існуючі міграції 0001–0005 |
| Deployment | GitHub Actions `.github/workflows/deploy-oselya.yml` |
| Telegram | Bot API webhook, menu button, Telegram WebApp JS SDK |

## 5. Безпека
- Telegram Mini App надсилає `initData` в заголовку `x-telegram-init-data`.
- Сервер перевіряє HMAC-SHA256 відповідно до WebAppData, термін дії `auth_date` до 24 годин і забороняє повтори ключів.
- Довіреними є лише Telegram ID зі **справжнього підписаного initData**. Переданий клієнтом owner ID ігнорується.
- Доступ до даних через `ALLOWED_USERS` або перевірене сімейне запрошення; SQL запити із параметризованими аргументами власника.
- У GitHub репозиторії немає BOT_TOKEN, WEBHOOK_SECRET, Cloudflare API token; вони зберігаються лише у GitHub Actions Secrets і Worker Secrets.
- API відповіді позначено `no-store`; UI та API працюють на одному HTTPS origin.
- Відкриття URL у Safari без контексту Telegram не дає доступу до приватних даних.

## 6. API-контракт
`GET /api/bootstrap` — повертає авторизований профіль, сім’ю, налаштування, осмоси, фільтри, аптечку, справи, покупки, витрати, історію й статистику.

`POST /api/action` — JSON із полем `type` і даними:
- `system.save`
- `filter.save`, `filter.replace`, `filter.delete`
- `medicine.save`, `medicine.stock`, `medicine.archive`
- `task.save`, `task.done`
- `shopping.save`, `shopping.done`
- `expense.add`
- `settings.save`
- `family.invite`, `family.remove`, `family.leave`

Дати — `YYYY-MM-DD`; кошти — копійки як цілі числа; зміни перевіряються на сервері. Користувацькі поля екрануються в HTML.

## 7. Тестування та публікація
- `npm test` перевіряє синтаксис Worker, календарні дати, аптечку, авторизацію, рендер HTML і виконуваність JS-коду.
- Автоматичний деплой: GitHub гілка `oselya-telegram-bot` → GitHub Actions → D1 migrations → wrangler deploy → webhook → `setChatMenuButton`.
- Для перевірки після релізу: відкрити бота на iPhone → меню «🏠 Оселя» → переглянути головну, додати тестову справу, препарат, фільтр, позначити заміну, перевірити сімейне запрошення.
- Обов’язкова перевірка вручну: сценарії Telegram WebView, оновлення даних на двох пристроях та сповіщення за розкладом. Успішний CI сам по собі не доводить усі інтеграційні сценарії.
